# Как запустить проверку

Этот файл лежит в главной папке проекта. Команды ниже нужно запускать именно из этой папки.

## Что это за проверка

Это автоматическая проверка сайта через браузер. Она сама:

1. открывает главную страницу;
2. вводит настроение и нажимает кнопку поиска картины;
3. проверяет, что при ошибке сайт показывает нормальное сообщение, а не ломается.

Интерфейс сайта от этого не меняется. Это проверка для разработки.

API-ключ Gemini для этой проверки не нужен: тесты используют фейковые ответы сервера.

## Как открыть командную строку в папке проекта

### Windows

1. Открой папку проекта `oracul` в проводнике.
2. Кликни по пустому месту в папке правой кнопкой мыши.
3. Выбери «Открыть в Терминале» или «Открыть окно команд».
4. Если открылся PowerShell или CMD — это нормально.

Можно также открыть CMD вручную и перейти в папку проекта командой `cd`, например:

```bash
cd путь\к\папке\oracul
```

### macOS или Linux

1. Открой терминал.
2. Перейди в папку проекта:

```bash
cd путь/к/папке/oracul
```

## Команды для запуска

Вводи команды по очереди, одну за другой.

### 1. Установить зависимости проекта

```bash
npm install
```

Эта команда скачает всё, что нужно проекту, включая Playwright.

### 2. Установить браузер для автопроверки

```bash
npx playwright install
```

Эта команда скачает специальный браузер, которым Playwright будет управлять автоматически.

### 3. Запустить проверку

```bash
npm run test:e2e
```

После запуска Playwright сам поднимет сайт, откроет браузер и выполнит проверки.

Если всё хорошо, в конце будет примерно так:

```bash
3 passed
```

Это значит, что все 3 проверки прошли.

## Если проверка упала

Если вместо `3 passed` появится ошибка, значит одна из проверок не прошла.

Обычно Playwright создаёт отчёт. Его можно открыть командой:

```bash
npm run test:e2e:report
```

Там будет видно, на каком шаге всё сломалось.

## Нужно ли деплоить сайт ради этой проверки

Нет. Деплоить сайт специально для этой проверки не нужно.

Проверка запускается локально на компьютере или автоматически в GitHub Actions внутри pull request.

## Что будет после merge PR

После merge эта проверка станет частью проекта.

Дальше при новых изменениях GitHub сможет сам запускать её и показывать результат рядом с PR: прошло или не прошло.
